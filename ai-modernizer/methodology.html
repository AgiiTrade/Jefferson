Methodology

Five phases. End-to-end. Auditable.

Modernization usually fails not because the new system is wrong, but because the old system is misunderstood. Agii's methodology is designed to fix that — by making the legacy estate readable before anything gets rewritten.

Start a Pilot See the Platform
PHASE 01

Understand

AI agents parse the entire legacy estate — millions of lines, multiple languages, embedded SQL, undocumented integrations. The output is a complete, navigable map of what exists today.

Typical duration: 1–2 weeks for a 500K–2M LOC estate.

Deliverables • System inventory with module-level metadata • Cross-program dependency graph • Business-rule catalog (extracted, not assumed) • Data-flow and integration map • Risk and complexity heatmap
PHASE 02

Map

Target architecture is drafted from the business rules, not from a pre-canned template. Source-to-target mappings produced for every entity, screen, integration, and batch job. Reviewed and signed off by your architects before any code is generated.

Typical duration: 2–3 weeks.

Deliverables • Target architecture blueprint • Field-level mapping specification • Integration contract (OpenAPI / events) • Phased modernization roadmap • Risk-adjusted cutover plan
PHASE 03

Transform

Agents co-author every module against the locked target architecture. COBOL becomes Spring Boot. Siebel scripts become Apex. RPG file definitions become PostgreSQL schemas. Your engineers review pull requests, not retype them.

Typical duration: 8–24 weeks depending on scope.

Deliverables • Generated target codebase (idiomatic) • Unit and integration test suites • Deploy templates (AWS ECS, Azure ACA) • Migration scripts and data tooling • Engineer-reviewed pull requests
PHASE 04

Validate

The reliability mesh runs logic-parity tests between the old and new systems. Drift, edge cases, and silent regressions are surfaced before cutover — not discovered by a regulator six months after go-live.

Typical duration: 3–6 weeks, run in parallel with later transform sprints.

Deliverables • Logic-parity test report • Side-by-side output reconciliation • Audit-ready evidence package • Zero-risk release plan • Rollback playbook
PHASE 05

Evolve

Once modernized, Agii doesn't disappear. The platform continues to monitor, document, and improve. New features and future changes get the same auditable, AI-assisted treatment that the modernization itself received.

Ongoing: monthly platform updates, continuous documentation.

Deliverables • Living architecture documentation • Continuous compliance posture • Tech-debt detection and remediation • Quarterly modernization review
Pilot Structure

Start small. Prove value. Then expand.

The fastest commercial path is a focused 6-week pilot — Phase 01 plus part of Phase 02 — on one codebase or one workflow.

Week 1–2

Discovery

One legacy codebase ingested. System inventory, dependency graph, business-rule catalog produced. Risk heatmap reviewed with your team.

Week 3–4

Analysis

Modernization candidates ranked. Issue clusters identified. Target-platform options scoped. Refactoring roadmap drafted.

Week 5–6

Modernization plan

Prioritized roadmap, work packages, and recommended next-phase implementation path. Executive-ready report for engineering leadership.
